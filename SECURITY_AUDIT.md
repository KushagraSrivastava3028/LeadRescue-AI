## Findings fixed during implementation

- Tenant-consistent composite foreign keys, explicit grants/RLS and membership helpers deny cross-tenant and forged-role access. Signed session IDs must still exist in `auth.sessions`; logout/revocation no longer depends only on JWT expiry.
- Database-level mutation throttles cover direct authenticated Supabase RPC paths as well as browser HTTP limits. Only owners can record a won job; owner removal/demotion remains protected.
- STOP is durably suppressed before acknowledgement; manual sends also need approved consent. Dispatch rechecks current eligibility and takeover. Unknown provider sends/purchases block blind retries. Queue publication and the outbox marker share one database transaction.
- Billing/admin risk holds survive ordinary paid reconciliation. First paid activation installs configured paid caps (initially 500 rather than the 100 trial cap); actual new periods reset once; same-period recovery preserves counters/caps. Actual provider price/interval/currency/quantity must match approved configuration. Eventless reconciliation does not advance the provider-event watermark.
- Customer confirmation is an explicit recipient POST, not a staff checkbox. Unknown bookings retain slot protection. Booking retries reconcile deterministic provider IDs before free/busy checks. Canceled entitlement, disabled days, DST gaps/ambiguity and overlap constraints are tested.
- Browser input remount/focus loss was eliminated. Mobile settings overflow and the hidden mobile account-page heading were fixed. Calendar inputs use business-local date/time rather than requiring customers/operators to enter implementation-level timezone offsets.
- Startup errors and provider responses are redacted; the worker's missing-config path no longer emits an uncaught diagnostic stack. CSP nonces require dynamic page rendering, which is enforced.

The initial full scan returned 19 generic patterns: generated private Next encryption/preview signing fields, one development HMR registration hash, and an exact synthetic password fixture. No external credential was found. Values were not printed; review recorded only field type and location. `.gitleaks.toml` documents narrow path-and-field exceptions for private framework-generated manifests and the exact fixture. Development-only HMR/cache is excluded because it is not shipped. Production browser bundles remain scanned. Private generated manifests remain secret server artifacts, are ignored by Git, and were verified inaccessible through local HTTP. Keep them out of static hosting, debug exports and public CI artifacts. No provider rotation was required on the evidence available; this does not assess secrets in an external account or unavailable history.

Gitleaks full redaction was verified in the tool help before scanning. Reports live only in ignored local cache and are not delivered or uploaded. The pre-commit hook scans staged changes, and CI scans source/build plus complete available Git refs. CI itself has not run on a connected remote repository.

## Remaining dependency finding

The final npm advisory snapshot reports **16 moderate transitive findings** across ESLint/Next lint plugins, typescript-eslint and minimatch. These are development dependencies; the runtime-only audit reports zero. Installed minimatch versions are 3.1.5 and 10.2.6. The reviewed advisory is [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), published/updated during this build period, concerning attacker-controlled glob amplification; its advertised fixed major is 11.0.1. Do not interpret an earlier clean registry response as the final result.

npm suggests a breaking force downgrade of ESLint. It was not applied. No incompatible cross-major override or advisory suppression was added merely to obtain a clean report. Track compatible upstream fixes, upgrade deliberately, then repeat lint/typecheck/build/tests. Repository lint uses developer-controlled glob configuration; the application does not offer arbitrary glob evaluation to customers. Untrusted CI contributions still require the normal restricted-token/secret boundary. This finding remains open and must be reviewed on the actual launch date.
